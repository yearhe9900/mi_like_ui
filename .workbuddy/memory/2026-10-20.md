## 透明参数收进统一配置（用户要求）

- 现状是「半统一」：`transparency_tokens.dart` 只有 blurSigma + 表面填充 alpha，
  搜索栏 13/36、顶栏压色 22 档采样色、按压高光 0.094、玻璃导航栏五层 alpha、
  按钮禁用态 12%/38%、亮色投影色，全散在各自 token 文件。
- 现在数值只在 `transparency_tokens.dart` 定义，组件 token 只引用常量 + 几何：
  - `blurSigmaRamp`（8 档 σ）是唯一来源，`MiGradientBlurProfile.bands` 由「段位/段高」
    两张几何表 + ramp 生成 → 副作用：`bands` / `MiTopBarPalette.blurBands` 从 const 变
    final（引用处共 2 处已改）。
  - 顶栏压色：`scrimGradientDark/Light`（const List<Color>）直接给 `LinearGradient.colors`，
    stops（比例位置，属几何）留在 palette。
  - 玻璃导航栏：alpha 具名常量（`glassScrimAlpha` … `glassLensTintLightAlphaTop/Mid/Bottom`），
    `Color.fromRGBO(20,20,20, MiTransparencyTokens.glassScrimAlpha)` 仍是 const 表达式。
  - 按钮禁用态：`disabledFillAlpha = 0x1F` / `disabledLabelAlpha = 0x61`。
- **必须保住原生表达形式**：0.63 之类实测小数维持 `fromRGBO`，不许换算成 161/255，
  否则黄金图会漂（0.63 vs 161/255 = 0.63137）。
- 守门：`test/transparency_config_test.dart`（6 例）扫源码 —— theme 层除配置文件外、
  组件层全部，不得出现 `withOpacity`/`withAlpha`/`fromRGBO` alpha 字面量/`fromARGB(数字`/
  带 alpha 的十六进制色；另有一条「配置文件自身必须带字面量」防空转。
  它当场抓到漏网的 `button_tokens.dart` 四条 `Color(0x1F…)`。
- 结果：159 项测试全绿、**零黄金图更新**（纯搬运）。

## 分类页也要膜（用户实机截图指出「你只是改了首页，分类没改」）

- 截图是**我们自己的 demo**（分类页滚动态，色块压在搜索栏/胶囊行后方）：色块直接
  透上来，胶囊边界只能靠文字认。
- 上一版 `overContent` 是**二选一**（有内容只铺膜 / 平底只留 6%），分类页这种
  「静止态背后是页底、滚动态才有内容」的页面根本没法开 —— 开了静止态胶囊就与页底
  同色消失。
- 改为**叠加**：膜垫在原填充之下，用 `Color.alphaBlend` 预合成单色
  （`MiTransparencyTokens.veiledFill`，零新增 render object、不给磨砂子树加 saveLayer）。
  核心性质：**膜取页底色 ⇒ 垫在同色页底上恒等于没垫**，所以平底不变、两态由背景决定。
- `veilAlpha` 按「两层叠完」重解：亮 117→153（0.60）、暗 150→167（0.655）。
  亮 `0.9412×(167+76a)=200`；暗 `0.9412×170×(1−a)+15=70`。平底仍 #E5E5E5 / #0F0F0F /
  #E7E7E7 / #242424（浮点差 0.3 级，已被 golden 吸收）。
- demo 分类页 `overContent: true`；`showcase_sticky_*` 与 `home_*` 预览刷新；
  `transparency_config_test` 新增「平底观感不变」四条断言。
- 教训：玻璃效果的正确打开方式是「膜垫底 + 填充在上」，不是一个状态开关 ——
  同一份配色在静止/滚动两态都成立，页面侧只需要回答「我下面会不会有内容」。

## 真机多出一条手势横条（edge-to-edge 的副作用）

- 现象：手机截图底部两条横条。实测 881×1920（scale 2.2417，屏 393×856.5dp）：
  - 上条：宽 309px=137.8dp、离屏底 **31.1dp** → **我们自绘的** `138×5`（`bottom: 9 + safeBottom`，
    反解 safeBottom≈19.6）
  - 下条：宽 281px=125.4dp、离屏底 **10.7dp** → **系统画的手势条**
- 成因：开了 `edgeToEdge` 后应用窗口铺到手势条下面，系统开始自己画那条条；示例外壳还照
  手机框老样子自绘一条 → 两条，且自绘那条比系统那条还高（9+safeBottom=31 vs 10.7）。
- 修：① 删掉自绘 Home 指示条（手机截图里的系统 chrome，不属于组件；桌面档也不该假装）；
  ② 底栏浮起量 `24.2 + safeBottom` → **`max(24.2, safeBottom)`** —— 24.2 是**距屏幕物理
  底缘**的实测值、手势条就落在这 24.2 之内，叠加后真机绿钮 bbox 反解栏底离屏底 45.05dp
  （比参考高 20dp、条悬在空档）；取大值后手势导航档回到 24.2、三键档（48dp）仍抬到按键上方。
- 教训：**edge-to-edge 之后，「安全区」不要一律加在已含安全区的实测值上**。先问这个
  实测值量的是窗口边缘还是屏幕边缘 —— 参考截图永远是屏幕边缘。
- 黄金图：`adaptive_phone` / `adaptive_small_window` / `demo_{dark,light}` /
  `goldens/demo_light_mine` 重生成（160 例全绿、0 error）。

## 搜索态：点搜索栏 → 真输入（参考「短信」搜索录屏）

- 录屏 592×1280 @**24fps**、79 帧（本机无 ffmpeg，用 `imageio.v3.imiter(plugin="FFMPEG")` 抽帧）。
- 实测（换算 s = 66/44.1 = 1.4966，用**同帧搜索栏高**标定，避免与既有 44.1 拉出偏差）：
  - 搜索栏 y 252…317 → **78…143**（168.4 → 52.1dp），**高度不变 66px = 44.1dp**；
  - 左缘 21px 不动；右缘 591 → 511；取消钮 ⌀66 = **栏高**、与栏隔 15px、右缘贴屏；
  - **四数闭合**：21 + 491 + 15 + 66 = 593 ≈ 屏宽 592（圆纵向也 66 → 没被帧边界裁），
    所以「右缘留白 0」是真的，不是漏算；
  - 叉号墨盒 26×25px = 17.0dp、笔画（45° 水平弦 4px）≈ 1.9dp；
  - 墨色分层：放大镜 167 / hint 161 / **叉号 0（纯黑）** → 叉号用前景墨色，不能用 icon 那档灰；
  - 光标 rgb(60,130,246)≈强调蓝、高 32px = 21.3dp、闪烁亮 12 帧 / 灭 12 帧 = 500/500ms（与 Flutter 默认一致）。
- 转场拟合：位移 `252 244 194 143 112 95 86 82 80 79 79 78`，**前 10% 静止 + easeOutQuint，
  总 480ms**（mean|Δ|=0.008；无延迟 easeOutQuint 0.035、easeInOut 族更差）。
  取消钮淡入**不与位移同步**：线性 0.35…0.62（208/250/292ms 覆盖率 0.32/0.63/0.96）→
  几何走 `Interval(0.10,1,easeOutQuint)`、透明度走 raw，两条曲线分开喂。
- 实现：`MiTopBar` 由 Stateless 改 **Stateful**（只为那一个 controller），但**构建逻辑留在
  widget 上的 `_buildBar(context, progress)`** —— 常规态每一处插值退化成原值，非搜索页逐像素
  不变（160 例全绿、零黄金图刷新）。内置 `MiSearchBar(editable:true)` 换 `TextField`
  （`InputDecoration.collapsed`，否则自带 12dp 内边距会把 hint 推离实测位置）。
- **两个「转场瞬间完成」的坑**（都踩了）：
  1. `late final _c = AnimationController(value: widget.isSearchMode ? 1 : 0)` —— 初始化器在
     **首次访问**（didUpdateWidget）才跑，那时 `widget` 已是新值 → 出生即 1.0。**必须在 initState 里建**。
  2. 宿主 `Stack` **条件插入**一层遮罩 → 兄弟按**下标**配对，顶栏从下标 1 挪到 2 →
     Element 被当成新子树重建 → State 重来。**Stack 子级增删一律给 ValueKey**。
- 位移那段在本 demo 为 0：参考页搜索栏在大标题下方（168.4dp）才会升到 52.1dp，本库头部区
  一直钉在状态栏下方、没有「标题 + 头部区」同页形态。README 与类文档都写明了这一点。

## 真机反馈两条：搜索态不收底栏 / 键盘压缩画面

用户实拍截图（搜索态 + 键盘弹出），两条：① 唤起搜索后不该有底部导航；
② 输入法出现后不该整体缩放。

- **底栏收起 = 换结构，不是淡出**：`MockPage.onSearchActiveChanged` → `DemoApp._searchActive`
  → 底栏分支改 `else if (!_searchActive)`。用 `Opacity` 会把含 `BackdropFilter` 的子树包进
  saveLayer（backdrop 变空 + 双份全宽高斯），玻璃栏当场变锐利 —— 与切 tab 不做 fade 同一条教训。
- **键盘压缩画面**：`DemoStage` 按可用高度取 `min(1, w/W, h/H)`，`Scaffold` 默认
  `resizeToAvoidBottomInset: true` 把 body 高度减掉 `viewInsets.bottom` → 393×856 画布整体等比
  缩水。改 `false`，键盘**覆盖**下半屏、画布恒定；搜索输入行本就在屏顶，下方那块是空的。
- 两条都写了会失败的回归用例（`search_state_test` 新增 2 例：底栏消失/装回、viewInsets 800+300
  下画面尺寸不变），并反向验证过（去掉修复 → 红）。
