### 判据 2（本批）：压在内容上还要一层「玻璃膜」

- **光磨砂不够**：模糊只改局部对比、不改局部均值。实测（同一 y、横向相邻取样）：
  - 亮：未选胶囊内侧 ≈200，间隙 ≈167 → **+33**；暗：内侧 ≈70，间隙 ≈170 → **−100**。
  - 上一版内置零件只留 onSurface@6% 的低调填充 → 我们的胶囊内侧 148 vs 间隙 164（−16），
    与参考反号、且在杂乱照片上读不出形状。
- 反解：亮 = 页底色 #F3F3F3 @0.46、暗 = 纯黑 @0.59（`MiTransparencyTokens.veilFor`）。
  平底页（分类页）那档 #E5E5E5 是**另一种状态**，两者不可互推。
- 落地：`MiPillTabBar` / `MiSearchBar` 新增 `overContent`（默认 false，平底行为不变）；
  `MiTopBar.overContent` 负责下发；demo 首页传 `true`。

## 透明参数收进统一配置（用户要求）

- 现状是「半统一」：`transparency_tokens.dart` 只有 blurSigma + 表面填充 alpha，
  搜索栏 13/36、顶栏压色 22 档采样色、按压高光 0.094、玻璃导航栏五层 alpha、
  按钮禁用态 12%/38%、亮色投影色，全散在各自 token 文件。
- 现在数值只在 `transparency_tokens.dart` 定义，组件 token 只引用常量 + 几何：
  - `blurSigmaRamp`（8 档 σ）是唯一来源，`MiGradientBlurProfile.bands` 由「段位/段高」
    两张几何表 + ramp 生成 → 副作用：`bands` / `MiTopBarPalette.blurBands` 从 const 变
    final（引用处共 2 处已改）。
  - 顶栏压色：`scrimGradientDark/Light`（const List<Color>）直接给 `LinearGradient.colors`，
    stops（比例位置，属几何）留在 palette。
  - 玻璃导航栏：alpha 具名常量（`glassScrimAlpha` … `glassLensTintLightAlphaTop/Mid/Bottom`），
    `Color.fromRGBO(20,20,20, MiTransparencyTokens.glassScrimAlpha)` 仍是 const 表达式。
  - 按钮禁用态：`disabledFillAlpha = 0x1F` / `disabledLabelAlpha = 0x61`。
- **必须保住原生表达形式**：0.63 之类实测小数维持 `fromRGBO`，不许换算成 161/255，
  否则黄金图会漂（0.63 vs 161/255 = 0.63137）。
- 守门：`test/transparency_config_test.dart`（6 例）扫源码 —— theme 层除配置文件外、
  组件层全部，不得出现 `withOpacity`/`withAlpha`/`fromRGBO` alpha 字面量/`fromARGB(数字`/
  带 alpha 的十六进制色；另有一条「配置文件自身必须带字面量」防空转。
  它当场抓到漏网的 `button_tokens.dart` 四条 `Color(0x1F…)`。
- 结果：159 项测试全绿、**零黄金图更新**（纯搬运）。
