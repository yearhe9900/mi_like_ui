## Switch 补齐（commit 11fd1ea / 994f3d4）

用户「Switch 按钮也加上」——本库早有 `MiSwitch`（但 demo 一直用 Material `Switch`，
从未陈列自己的），所以这轮 = **补交互 + 换 demo**。

### 补齐的三个交互（对齐 flutter_miuix `MiuixSwitch`）
- **水平拖拽切换**：`_ctrl.value += delta / travel`（直接跟手）；松手 `>= dragSwitchThreshold`(0.5)
  即 `onChanged(!value)`；归位 `addPostFrameCallback` 里按**最新** `widget.value` 决定
  （宿主同帧接受→弹新端，拒绝→弹回原端），比上游「直接 `_animateThumbPos(widget.value)`」更稳。
- **钮体按压放大 1.127**（上游参考值），过渡**复用** `MiMotionTokens.pressMs/pressCurve`
  （不另造时长）；用 `TweenAnimationBuilder` 跟随 `_active`。
- **RTL 镜像**：`right: left` 定位 + 拖拽 delta 取反。

### 关键手法：按下态怎么拿
`MiPressable.pressBuilder` 只能拿到 `pressed` 且只能包整体子树 → 给不了「只放大钮体」。
解法：外层 `Listener(onPointerDown/Up/Cancel)` 自己跟踪 —— **Listener 不参与手势竞技场**，
不会抢 `MiPressable` 的 tap；拖拽用内层 `GestureDetector(onHorizontalDrag*)`（更深→优先，
tap 会被自动 cancel，不会双触发）。

### 坑
- demo 里有 `find.byType(Switch)`（Material）的测试断言 3 个文件 6 处：`desktop_nav_test`、
  `light_mode_golden_test`、`preview_capture_test` —— 换组件后**必须同步改**，否则
  「Found 0 widgets with type Switch」。
- 新增陈列后 `find.text('禁用态')` 撞车（开关/复选框各一行）→ demo 标签改
  `禁用态（开关）`/`禁用态（复选框）`；`已开启` 与 WLAN 行 value 撞车 → 热点行改
  `已连接/未连接`。**测试按文本定位时，demo 文案要保证唯一**。
- `scrollUntilVisible` 的 finder 必须唯一，否则 `Bad state: Too many elements`。
