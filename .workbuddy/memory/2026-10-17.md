## 顶栏第 3 轮：材质改为「渐进磨砂」（推翻上一版「纯色遮罩」结论）

**用户诉求**（附录屏 `Screenrecorder-2026-10-17-12-25-51-790.mp4`，1220×2656 / 24.26fps /
6.64s）：`我发现顶部导航栏不内嵌任何组件，目前项目中顶部导航栏模糊效果和这个不一致，
请复刻视频中的效果`。

### 结论：上一版「顶栏无 backdrop 模糊」是**误判**

上一版的证据有两条，都站不住：

1. 「沿蓝卡填充色纵向取样得亮度斜坡 0.01…1.00（64.4→128.9dp）」—— 平坦色块在模糊下
   亮度**不变**，该斜坡只能来自叠色；但取样列落在卡片**顶缘之外**时同样会读出斜坡，
   无法区分；
2. 「卡片下缘 113 → 0 在 3px 内完成（无拖尾）」—— 该卡片顶缘在 183dp，本来就在
   模糊带（≤119dp）**之下**，当然锐利。

换成**高频内容**（头像照片的圆边、圆角方块的竖直边）后，模糊是确定性存在的。

### 实测（亮色「我的」页，s = 393/1220 = 0.32213 dp/px）

有效 σ（dp），两条独立方法交叉验证（边缘 10-90 宽度 / 同行频谱比）：

| y (dp) | 0…35 | 50 | 67.5 | 90 | 103 | 109 | ≥119 |
|---|---|---|---|---|---|---|---|
| σ | 5.37 | 4.96 | 4.34 | 1.85 | 0.76 | 0.27 | 0 |

`blurSigma = 5.37`（平台段 42.7px / 2.563 × 0.32213）。

叠色（**关键判据**，两处平坦区交叉验证）：
* 同帧页底 #F3F3F3(243) 在栏内**全程不变** → 排除白色叠色；
* 白卡填充 255 在栏内 80dp 读 **249**，同帧栏外读 255 → 排除"无叠色"，
  249 = 255 − (255−243)×0.50，即 **叠色 = 页底色 @α**；
* α(y) 由 1-D 逐行反卷积 + PAVA 单调平滑：0.650(顶) → 0.594(57) → 0.501(88) →
  0.314(103) → 0.055(118.5) → **0(122.4dp)**。

遮罩 m(y) 由边缘宽度反解（模型 `观察值 = (1−m)·原内容 + m·模糊(原内容)`）：
1.00(0…35) → 0.98(34.6) → 0.85(50.1) → 0.67(67.5) → 0.30(90) → 0.24(102.9) →
0.14(108.7) → **0(119)**。

### 实现

* `ShaderMask(blendMode: dstIn, shaderCallback: blurMask)` 包 `BackdropFilter`
  （`ClipRect` 在外）→ 遮罩为 1 处只留模糊、为 0 处只留原内容，正好是上式。
  **不能用半透明色层模拟**（只压暗、不抹细节），也不宜用多层 `ClipRect` 分段
  （分段边界在模糊场上留接缝）。
* `MiTopBarPalette` 新增 `blurSigma` / `blurMask`（明暗通用）；浅色 `scrimGradient`
  换成实测 α(y)（12 stop）；深色配方不动。
* `MiTopBar.title` 改可空 → **纯材质形态**（不内嵌任何组件，高度收到 `scrimHeight`），
  与录屏同构；`showBack` 仍可单独用。

### 测量脚本（`.workbuddy/`，分析用不入库）

`measure_top_bar_blur2/3.py`（边缘宽度，竖直边缘避开运动模糊）→
`measure_top_bar_track.py`（内容位置轨迹）→ `measure_top_bar_sweep.py`（头像边缘随 y）→
`measure_top_bar_spec.py`（频谱比）→ `measure_top_bar_fit.py`（逐行反卷积，注意窄窗口

（PAVA 平滑 + 输出 Dart 字面量）。

## 续：ShaderMask 方案被实测推翻 → 改为分段定 σ 阶梯

用户在本轮明确「你自己执行命令」，之后 analyze / test / 黄金图生成都由 agent 执行。

### 关键发现（探针实证，不是推测）

**`ShaderMask` 包 `BackdropFilter` 时，只要遮罩出现 alpha<1，模糊就整段消失。**

探针（260×120 黑白色条底 + 顶栏带，独立 4 组）：

| 变体 | 结果 |
|------|------|
| `ClipRect + BackdropFilter(σ=5)` | 条纹明显抹平 ✔ |
| 同上 + `ShaderMask(dstIn, alpha 恒 1)` | 仍糊 ✔（Skia 优化掉了恒定不透明的 saveLayer） |
| 同上 + `ShaderMask(dstIn, 任何含 <1 alpha 的 gradient)` | **完全恢复锐利** ✘（哪怕顶部 alpha 就是 1） |
| 「多段并列 `ClipRect+BackdropFilter`，σ 递减」 | 逐段生效、强度按 σ 递减 ✔ |

原因：半透明混合会引入新的 saveLayer，`BackdropFilter` 的 backdrop 随之变空。
所以「用遮罩把定 σ 模糊按 m(y) 削弱」这条路在 Flutter 里根本走不通。

### 改法

* 删除 `MiTopBarPalette.blurMask`，新增 `blurBands`（`List<MiTopBarBlurBand>`，
  `top/height/sigma` + `MiTopBarBlurBand` const 类，带 `==`/`hashCode`）。
* 8 段定 σ：[0,35) 5.37 · [35,50) 5.15 · [50,67) 4.68 · [67,78) 3.80 ·
  [78,90) 2.50 · [90,100) 1.45 · [100,109) 0.70 · [109,119) 0.30。
  σ 取实测控制点 (0,5.37)(35,5.37)(50,4.96)(67.5,4.34)(90,1.85)(103,0.76)(119,0)
  的分段线性插值在**段中点**处的值；段高 ≤17dp、相邻 σ 比 ≤2.4（σ 越小越不可辨）。
* `top_bar.dart` 里磨砂层改成 `for (final band in MiTopBarPalette.blurBands)
  Positioned(top: band.top, height: band.height, child: IgnorePointer(ClipRect(
  BackdropFilter(σ: band.sigma, child: SizedBox.expand()))))`，不再有 ShaderMask。
* 测试改 3 例：token（无缝/单调/σ 比/与实测曲线对齐）、磨砂层（N 个 BackdropFilter、
  逐个几何、拼起来 0…119、**断言不得出现 ShaderMask**）、纯材质形态。

### 顺带修掉的两个既有用例错误（全量首跑暴露）

* `button_test`：宽度断言写死 `2*13 + 2*17 = 60`，但本 SDK 测试字体 CJK advance
  是 1.019em（「关注」13dp = 26.5）→ 实测 60.5 挂。改为
  `btn.width == text.width + 2*padding` + `width < 屏宽`。
* `top_bar_test` 两例（含本轮新增的「无标题也可显示返回圆钮」）：`onBack == null`
  时圆钮退化成 `IgnorePointer`、**没有 GestureDetector**，而 `_backHitArea` 就是按
  GestureDetector 找的 → 改为显式传 `onBack: () {}`（「null 不参与手势」那例反过来
  显式写 `onBack: null`）。

### 结果

`flutter analyze` 0 error / 10 info（全是既有项）；`flutter test` **72 项全绿**；
`doc/preview/*.png` 已重生成 —— 顶栏四格第一张（纯材质形态）里头像/昵称条/蓝卡顶缘
明显被抹开、越往下越锐利，终于和录屏一致。

## 丢帧排查与模糊层优化

用户反馈"感觉 app 丢帧"。先量化：一次 build 里的 BackdropFilter 层数 + 覆盖面积
（每帧全 QUAD 高斯，滚动时 backdrop 一变就重算，是滚动掉帧主因）。
基线（深色平板 768×1280）：首页/我的 **10 层 / 100,073 dp²**、分类 **6 层 / 58,009**。

三条零视觉差异优化（改后逐像素对比：最大差 1~2 级、无像素差 > 2）：
1. 深色顶栏跳过 0…63.6dp（scrim α=1.000 纯黑盖住模糊）→ 8 段/119dp 变 5 段/45.4dp；
   亮色 α=0.650 一段不省。新增 `MiTopBarPalette.scrimOpaqueBottom` +
   `MiTopBar.visibleBlurBands`（@visibleForTesting）。
2. 胶囊行 4 个 BackdropFilter 合并成 1 个（`_CapsuleStripClipper`）；分类 6→3 层。
3. `ImageFilter` 按 σ 缓存（`src/utils/filter_cache.dart`）+ 跳过 σ<0.5dp 的段。

另发现**切页 fade 是双重问题**：`FadeTransition` 的 Opacity 会 saveLayer → 旧页
backdrop 变空（磨砂在 260ms 里消失），且两页共存（实测层数 7→9、6 层 opacity）。
去掉 AnimatedSwitcher 后 mid 帧 = 3 层（与新页一致），切页瞬时完成。

结果：首页/我的 10→6~7 层、100,073→47,081 dp²（**-53%**）；分类 6→3 层。
新增 `test/perf_budget_test.dart`（层数/面积预算 + 深色段不落在不透明区 +
亮色从栏顶开始 + 同 σ filter 跨帧复用）。`dart analyze` 0 error、
`flutter test` **94 项全绿**；preview/黄金图已重生成。

提醒用户：**debug 模式下渲染开销是 profile 的数倍**，"感觉丢帧"先排除 debug。

## 续：顶栏通用化 —— 头部插槽（搜索栏 / 胶囊行）

需求：把顶栏抽成可复用通用组件，并把分类页里手写的「搜索框 + 胶囊行吸顶头部」
收进组件内部统一渲染，同时保持既有功能与交互不变。

### 改动

* `MiTopBar` 根节点从「定高 `SizedBox(Stack)`」改成
  `SizedBox(width: ∞, child: Column(min, stretch, [标题区定高, 头部区]))`。
  标题区 = 材质 + 大/紧凑标题 + 返回圆钮（高度 `titleExtent`：有标题
  `componentHeight`、否则 `showSurface ? scrimHeight : 0`），与原行为一致
  （既有 24 条用例全绿，标题形态高度未变）。
* 新增插槽 `searchBar` / `tabBar` / `header`（`PreferredSizeWidget`），三者互斥
  由构造期断言保证；另有 `searchBarHeight` / `tabBarHeight` / `headerInset` /
  `showSurface` 可配置。
* 新增 `occupiedHeight(context)`：宿主给滚动内容让位用它，
  `padding.top = occupiedHeight + MiTopBarMetrics.headerContentGap`。
* `MiTopBarMetrics` 新增 `headerTopInset` 56 / `headerTopInsetFor(safeAreaTop)` /
  `searchBarGap` 16 / `headerContentGap` 12 / `headerInset` 11.9 /
  `searchBarSlotHeight` 44.1 / `tabBarSlotHeight` 39.9。
* 分类页删掉 `_headerHeight()` 与 `_statusBarInset()`（后者的语义已收进
  `MiTopBarMetrics.headerTopInset`，`dart:math` import 随之删除）。

### 设计要点（写进 MEMORY.md 了）

* **插槽高度是声明值**（组件排版 + 宿主让位共用同一套数字），换成自定义高度的
  组件时必须同步传高度，否则列表让位会错。
* **胶囊行满宽、不吃 `headerInset`**：它自带 11.9 `edgeInset`，且横向滚动要能
  出血到屏边；套内边距会让末尾胶囊多裁 30dp 左右。搜索栏与 `header` 才吃。
* `showSurface: false`（分类页用）：搜索栏/胶囊各自已有 backdrop 磨砂，参考页
  也没有整条磨砂底；开着会多 8 层模糊、并把两者间隙染上叠色。
