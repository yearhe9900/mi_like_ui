## MiMenu 行距修复（GitHub issue #6）

- 取 issue 改用 **GitHub CLI `gh`**（仓库 `yearhe9900/mi_like_ui`，分支 `main`；本工作区 remote 是 GitHub 不是 CNB，`cnb issues` 那条路走不通）。`gh issue view <n> -R owner/repo --json title,body,state,labels,comments` 拿正文（纯 `gh issue view` 输出为空，必须带 `--json` 或 `--comments` 才出内容）。push 目标也是 `main`，不是 `master`。
- 根因：`_trailingFor` 的勾号 `SizedBox(20,20)` 参与行高，而正文行盒 `dialogAction` = 15.9dp/`height: 1.0` ⇒ 选中行比普通行高 4.1dp，上下相邻中心距各 +2dp（真机 42 vs 40）。
- 修法：装饰槽 `SizedBox(width, height: 0)` + `OverflowBox(maxWidth/maxHeight 为墨盒尺寸)`，装饰按行中线居中溢出绘制；2.05dp 溢出落在 12dp 行内边距里不碰邻行。级联返回行的左箭头同一处收口。首/末行 20dp（参考实现刻意更松）**未动**。
- 回归测试：`test/menu_test.dart` 新增「行高：勾号不参与行高」，断言选中行高 == 普通行高、== `rowPadY*2 + 15.9`（引擎把行盒取整到 16.0，容差给 0.2，给 0.01 会挂）、选中行两侧中心距 == 普通行中心距。
- 预览图 `doc/preview/menu_light|menu_dark.png` 需 `--update-goldens` 重生（cascade 那张没变）；先读 `test/failures/*_master|testImage.png` 做 numpy 差值确认 bbox 只在面板矩形内（181,198–380,284）。

## Button / Slider 落地 flutter_miuix 能力（a88361b / 16ad377 / cb1a837 / 2082c29）

### 先答「菜单项是否用了参考的 Item」
- 参考里 Menu 的项 = `MiuixDropdownImpl`（`miuix_dropdown.dart`，渲染
  `MiuixDropdownItem` 数据类）；另一变体 `MiuixGlassPopupItem` 是玻璃弹层专用、
  上游自身也没接线。
- **本库 `MiMenu._row` 结构与尺寸就是照它实现的**：`MiMenuMetrics` 顶部那张
  「本类 ↔ 参考字段」表逐项对应（rowInsetX 20 / rowPadY 12 / rowEdgePadY 20 /
  iconCell 26 / iconGap 12 / checkSide 20 / trailingGap 12 / arrowSize 10×16 /
  分隔线 1.5·20·4 / 面板 200–288·圆角 16 / 0.15 缩放起手 / ζ0.82·k362.5 /
  200·150ms 淡入淡出 / 遮罩 300·150ms）。选中态**只换文字与勾号色、不铺底** ——
  上游默认 `containerColor == selectedContainerColor == surfaceContainer`，
  本库行为与之等价。
- 三处**刻意不同**（已写在注释里）：① 行尾装饰不参与行高（上游参与；它正文行盒
  18.7 与勾号 20 差 1.3dp 看不出，本库 15.9 差 4.1dp 会看出来 —— 就是 issue #6）；
  ② 按压视觉走 `MiPressable` + `MiTransparencyTokens`，不引上游 pressed color；
  ③ 文案限宽是「面板 288 − 内边距」的动态上限，上游 popup 模式固定 216dp。
  另：级联回退行用左向箭头（语义「回上一级」），上游复用右向箭头。

### Button（对齐 `MiuixButton`）
- 能力面照抄、几何不动：常规档仍是 28.3dp stadium 度量。新增 `text` 形态、
  `large` 档（40 / 20 / 15dp，参考实现值，新增 `MiTypography.buttonLabelLarge`）、
  `icon`（16dp 定尺 + 6dp 间距）、`child`（与 label 二选一，文字继承标签样式）、
  `minWidth`（**默认不给**，不搬上游 58dp）、`enabled` 与 `onPressed` 解耦。
- 文本形态禁用时**填充保持透明**、只降墨色 —— 别顺手填 disabledFill。
- `minWidth` 走 `AnimatedContainer(constraints:)`，`null` 时不加层 → 默认结构零变化
  （按钮测试的 `width == 文案 + 2×内边距` 断言因此没改）。

### Slider（对齐 `MiuixSlider`，几何仍是本库细轨推导档）
- **改 StatefulWidget**，显示值走 `AnimationController.unbounded`：
  拖拽直接 `_valueCtrl.value = v`（不每帧起弹簧）→ `didUpdateWidget` 有
  `_dragging` 守卫（否则双重动画）→ 点按 `animateWith(settle)`。
- **归位判据沿用 MiSwitch**：`onChangeEnd` 后 `addPostFrameCallback` 用「最后一次
  上抛的值」对比宿主值，宿主动态没接受就帧末弹回，不猜宿主是否同帧 setState。
- 拇指贴边行程：`圆心 = 直径/2 + t×(宽 − 直径)`，0 / 1 不再探出控件；旧映射
  `width * t` 在两端各探出 10dp。测试「拖到 0.5」在新旧映射下同值（中点不变），
  旧用例无需改动。
- 关键点：`keyPoints` 给出即显示（不依赖 `showKeyPoints`），`showKeyPoints` 才展开
  `divisions` 等分刻度；选中判定用「t 与点的 t 比较」而非像素比较。
- 量化顺序：先分档（divisions 优先），再关键点磁吸 —— 与上游「steps 优先」一致。
- `divisions` = 档数（含两端），上游 `steps` = 中间台阶数 → `divisions = steps + 2`
  （已写进 USAGE）。
- 触感**不代发**（与 MiSwitch / MiCheckbox 同口径），只在文档里给自行触发的写法。
- 新 `theme/slider_tokens.dart`（`MiSliderPalette`）：白钮、关键点选中白 / 未选
  中深浅两档灰（推导，轨道本身是 onSurface@12%，灰点要离开轨道）。

### 坑（这轮踩到的）
- `late final AnimationController(...)` 必须在 `initState` 建（初始化器首次访问才跑）。
- 测动画：`startGesture` → `moveBy` → **先 `pump()` 让 ticker 起跳，再
  `pump(200ms)`**；只 pump 一次 200ms 时动画从该帧才开始，读到的仍是初值。
- 断言放大倍数要把 `key` 挂在 `Transform.scale` 上（挂在内层 DecoratedBox 上
  `getMaxScaleOnAxis` 会读错祖先）。
- `Row(mainAxisSize: min) + Flexible` 在**无界宽**父级里会报错；常规用法（有界父级）
  才安全，长文案仍能省略。
- analyze 新增 `prefer_const_declarations` 3 处：`final` 常量改 `const`（hitRadius /
  thumbTop / thumbRadius）。

- `flutter analyze` 0 error / 101 issues（本轮新增文件零提示）；`flutter test`
  **434 passed**（本轮新增 13 例：按钮 5 / 滑条 8），黄金图与预览图基线
