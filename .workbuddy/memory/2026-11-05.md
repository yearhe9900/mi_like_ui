## 新增 MiMenu 锚定菜单（7913608 + 455949b + 3bf6462 + 1067fd2，已 push）

- 参照物：`flutter_miuix` 的「Menus」不是单个组件而是 `Miuix*DropdownPreference` / `MiuixListPopup` / 级联弹层的陈列页。本库没照搬 preference 层（设置行已存在），只抽出一个 `MiMenu`：**只量 child 盒子做锚点、不接管点按**，靠 `MiMenuController` 开合 —— 这样 `MiSettingsRow` 自己就是入口。
- 落位：`lib/src/overlays/menu/`（`menu.dart` / `menu_metrics.dart` / `menu_painter.dart`）。放浮层的原因不是「弹层」而是分层：`overlays` 不许 import `components`，菜单要包任意 widget 做锚点，进 components 会逼它反向依赖。
- 定位是纯函数（`MiMenuMetrics.panelOffset` 右缘对齐 → 下方优先 → 翻上方 → 夹紧宿主；`revealFromBottom` 决定缩放原点），可单测，不依赖 RenderBox。
- 两个坑：①面板经 `MiPopup` 渲染到宿主，**宿主在页面 Scaffold 之外**，缺 `Material`/`DefaultTextStyle` → 文字变方框 + 黄下划线（给面板补 `MaterialType.transparency`）；②弹簧落定在 0.9999 而非 1，缩放层让面板窄 0.1% → 宽度断言放宽到 ±0.5dp（别收紧回 0.01）。
- 级联二级「返回行」的箭头要**水平镜像**（`MiMenuChevronPainter(back: true)`），照抄参考会朝右、看着像进入下一级。
- 预览图必须把 `MiPopupHost` 放进**截图子树内**（`KeyedSubtree` 里），否则只截到被压暗的页面、面板在 golden 之外。
- 验证：`flutter analyze` 新增文件零告警（lib 16 条 / test 88 条均为既有）；`flutter test` 415 全过（menu 9 例 + 展示页 2 例 + 预览 2 例）。提交拆 4 个语义提交后 push，`main...origin/main` 同步。

## 级联切换对齐参考实现（3a995a7 + 8909df0，已 push）

- 用户对比 flutter_miuix 指出「级联菜单动画不一致」，随后发来参考 App 的录屏。**录屏取证方法**：本机没有 ffmpeg，但 venv 里有 `imageio` + `imageio_ffmpeg`（自带 ffmpeg 7.1 二进制）→ `imageio.imiter()` 逐帧导出 PNG，再用 PIL 拼缩略图/条带/原尺寸网格逐帧看；**判据不是猜，是把两边同一时刻的帧并排**。顺带：抽帧后用帧间差找事件帧（本例 24fps、176 帧）。
- 录屏里参考侧的级联切换 = **两层内容就地淡换**：行数相同（4 行 → 4 行）所以面板尺寸恒定，新旧两层按行成对重叠（新建/分享到、打开/微信…）。
- 本库当时三个偏差：①返回行漏抄父项副文 → 首行比原行矮，整列上移，两层行错位看着像「两页错乱叠字」；②滚动体在切换子树**外**（两层共用一条滚动轴）；③演示菜单两层行数不同（3 vs 4）→ 面板先长高再落定。三条都按参考改了（`_levelView` 每层一条滚动体；`AnimatedSwitcher` 仍是 200ms / easeOut+easeIn / 0.95→1 / 顶层 Stack 顶对齐）。
- 保留差异：返回行箭头**保持左向**（`MiMenuChevronPainter(back: true)`）—— 用户 2026-11-05 明确「不改，你的理解是对的」，参考的右向只是复用没改方向；不要再照参考翻回来。
- 尺寸过渡（`89fb9d3`）：`AnimatedSwitcher` 默认 `layoutBuilder` 按**两层最大值**定栈尺寸 → 面板先跳到最大、收敛后再缩回，行数不同时就是瞬跳 + 二次跳。改成自定义 `layoutBuilder`：退出层 `Positioned(top/left/right)` **不参与定尺寸**、拿当前层的 tight width（两层按行对齐），栈尺寸 = 当前层；外面套 `AnimatedSize(200ms, easeOut, AlignmentDirectional.topCenter)` 让宽 / 高跟随内容插值（= Compose `AnimatedContent` 的 `SizeTransform` 语义，Flutter 移植版没做）。实测逐帧高度 166→175→183→191→197→202→205→206 单调减速、无过冲。`Positioned` 不带 bottom → 子级高度靠 `.enforce(constraints)` 拿到有限 maxHeight，`SingleChildScrollView` 不会报 unbounded。
