# 2026-10-23

## 宽屏（桌面 / 平板）优化第一批

用户在「移动端尚可，桌面端和平板表现一般」后回「先这么修改」—— 落地我提的第一批：
**内容上限 + 区块响应式 + 卡片比例 + hover/光标 + 滚动条**。

- **根因**：所有几何都在 393dp 上实测，宽屏只是等比拉伸，没有一条宽屏专属规则。
  1366 预览实拍可见：设置行被拉成 1220dp、两个演示按钮变超宽色条、6 张竖版卡
  186×339（一屏 1.4 行）、搜索栏 1197 宽、侧栏 95×177 浮在空白里。
- **新增基础件**：`MiBreakpoints.contentMaxWidth`(1120) + `MiContentColumn`；
  `MiBreakpoints.columnsForMaxCell` + `MiResponsiveGrid.maxCellWidth/maxColumns`；
  `MiThemeCard.previewAspectRatio`；`MiHoverFeedback` + `hoverOverlayFor`(5.6%)；
  `MiDimens.spaceXxxl`(32)。
- **示例**：`_homeSections` 改函数（双卡宽幅比例 1.15/1.9/2.45、四卡区 2/4/4 列网格）；
  `_GradientCard` 由固定高改 `aspect`；主题卡网格 `maxCellWidth: 240`（平板停 3 列 =
  3+3）+ 桌面横版 16:10；「我的」页内容列 720；三页 `Scrollbar(thumbVisibility)`。
  手机档数值一律不变（172×150、3 列、4.1:1 与素材一致）。
- **坑**：`MiContentColumn` 必须**恒定套着**（不按 framed/断点增删），否则页面 Element
  重建、跨断点滚动位置归零 —— 与之前 `clipBehavior` 那条同源。
- **坑**：`maxCellWidth` 会让「mediumColumns: 3」失效（736 宽时 `ceil` 算出 4 列）→
  把上限抬到 240 才真的停在 3 列。列数取「断点台阶」与「上限列数」较大者。
- **验证**：208 例全绿、analyze 0 error；桌面每帧模糊面积 211,132 → **191,615 dp²**
  （内容列封顶，预算收紧到 196,000）；预览/黄金图重生成（adaptive_* / demo_*）。
- 数值全是推导（素材只有手机档），README 新增「宽屏配方」「指针悬停」两节并写依据。

## 宽屏第二批（「全做」—— 展开侧栏 / 顶栏收敛 / 键盘 / 桌面弹窗转场 / 悬停操作条）

- **展开侧栏**：`MiGlassSideNavBar.expanded` + `MiBreakpoints.usesExpandedRail`
  （容器 ≥1024，与 desktop 同值）；240dp（推导，Material/WinSettings 200…320 档），
  条目改横排 icon+label，`expandedItemWidth = 240 − 2×6.6 = 226.8`、内缩 18、图文距 12。
  平板仍窄栏（让 240 会吃三成画布）。**Row 必须钉 expandedItemWidth 定宽** ——
  外层 Column 是居中对齐，不定宽会按自然宽居中、内缩就不从胶囊左缘量起。
- **顶栏三参数**（手机传默认值逐像素不变）：`headerTopInset`（桌面 24）、
  `searchBarMaxWidth`（桌面 520）、`actions`（右侧动作区，搜索转场淡出退排版）。
  `_searchRow` 分手机 Stack / 宽屏 Row 两条路径 —— 手机路径一字未动。
- **键盘**：`MiFocusRing`（Focus + 边界外 2dp 描边，实色 AnimatedContainer、
  未聚焦全透明 → 黄金图零变化；Enter/Space 激活）接进 `MiButton`；
  `MiSearchShortcuts`（⌘/Ctrl+K、Esc）在示例层。
  **坑①**：本 SDK `sendKeyEvent` **没有修饰键参数** → 用
  `sendKeyDownEvent(modifier)` + `sendKeyEvent(key)` + `sendKeyUpEvent` 组合。
  **坑②**：`find.byType(Focus).first` 会先命中 MaterialApp 自己的 Focus → 必须
  `descendant(of: MiFocusRing)` 限定。
  **坑③（踩了才修）**：`_keyboardScope` 写成「compact 原样返回 child」→ 跨断点
  增删包装层 = 换 Element = 滚动位置归零（desktop_nav 跨断点测试红）。改成
  **三档恒挂、只切 `autofocus`** —— 与「内容列恒定套着」同一条坑。
  手机档 `autofocus: false`：抢焦点会把搜索光标闪烁相位推偏（黄金图 0.01% 差）。
- **桌面弹窗**：`MiDialogMetrics.isWide(容器宽 ≥1024)` → 居中限宽 440 / 圆角 16、
  `position` 失效；正文行数按**实际卡宽**排。手机档用 `left/right=sideMargin`
  **自适应**（不能写死 width 369.2 —— 窄容器会溢出、平板原行为是撑满边距之间）。
- **桌面路由**：`MiCardPageRouteMetrics.isWide(窗口 ≥1024)` → 4dp 抬起 + **同色
  幕布**（ColoredBox 页底色 alpha 1→0）220ms（`Interval(0,0.55)` 落在原 400ms 里，
  transitionDuration 构造期定死拿不到窗口宽）、圆角 ≤16；下层无视差不压暗。
  **不能用 Opacity/FadeTransition** —— 新页含磨砂顶栏，saveLayer 清空自己的
  backdrop。幕布 key = `MiCardPageRoute.wideVeilKey`（测试读 alpha 用）。
- **悬停快捷操作**：`MiHoverFeedback.onHoverChanged` + `MiThemeCard.quickActions`；
  条 = 黑@45%（新 token `cardQuickActionsScrim`）+ `AnimatedSlide` 滑入（Transform
  无 saveLayer）、IgnorePointer 联动 ignoring。quickActions==null 不挂（手机档）。
- **滚动降 σ**：`MiGradientBlur.sigmaScale` / `MiTopBar.sigmaScale`（默认 1.0），
  demo 滚动中 0.6、停 120ms 恢复（`_scrolling` + Timer 120ms）。
  形状（段位/段高）不变只改强度；低于 minVisible 的尾段照常剔除。
  两档 σ 各自进 `MiFilterCache`。
- **模糊预算重标**：桌面 191,615 → **214,182 dp²**（展开栏 +144.6dp 宽，层数仍 2），
  阈值 196,000 → 220,000，README 表同步。
- **验证**：244 例全绿、analyze 0 error/warning；**手机/平板预览图零变化**，
  只有 adaptive_desktop{,_light,_showcase} 三张重生成。CHANGELOG 加第二批条目，
  README 更新侧栏两形态表 / 顶栏参数 / 宽屏配方 +5 行 / 新增「键盘可达性」节。
