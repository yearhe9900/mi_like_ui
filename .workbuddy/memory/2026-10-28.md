# 2026-10-28

## 搜索转场提速 + 去丢帧（原地 + 推入两条路径）

用户反馈：搜索栏点击后 / 退出的动画「不够干脆、丢帧、速度慢」。按「两处都改」处理。

**时长（手感优先，形状不动）**
- `MiTopBarMetrics.searchTransitionMs` 480 → **220**。素材量到 480 = 起手静止 48 +
  位移 430；`Interval(0.10,…)` 与取消钮淡入段 `0.35…0.62` 都是线性时间比例 →
  按同一比例压缩（静止 22ms、淡入 77…136ms），曲线与相位关系完全不变。
- `MiCardPageRouteMetrics.durationMs` 400 → **300**（实测拟合 400 仍是原值注释里
  的结论；曲线 easeOutCubic 不动）；桌面档 220ms 由 `wideVisualFraction`
  自动变成 220/300 ≈ 0.73。

**丢帧根因（两条都在「含磨砂的子树」上犯了同一类错）**
1. `Opacity` 包胶囊行 / 取消钮 → saveLayer 清空子树里 `BackdropFilter` 的输入
   （磨砂整段消失）＋ 每帧一次离屏合成。改：新增公开参数
   `MiPillTabBar.fade` / `MiSearchCancelButton.fade`，把系数乘进**各处颜色的
   alpha**（填充 / 标签墨色 / 膜带 / 亮边 / 叉号墨 / 按压盘）。`MiPillTabBar`
   在 fade<1 时把 `AnimatedContainer` 的 duration 收成 0（否则 200ms 的填充
   色插值会把淡出拖成长尾）。
2. 顶栏 `materialHeight` 逐帧插值 → 头部磨砂 9 段 `ClipRect` 每帧重定位，整条
   头部区全宽高斯每帧重跑。改：转场期盒高钉在常规态高位（`searching && t<1`），
   只在端点收一次；两端跳变都被搜索态底色 / 已淡到 0 的胶囊行盖住，看不见像素。

**顺带**：`_MiPushParallax` 的 `LayoutBuilder + Transform.translate` 换
`FractionalTranslation`（绘制期平移，不再每帧跑一次布局）。

**守门测试**（`search_state_test`）：① 磨砂段矩形在转场中必须逐值恒定；
② 胶囊行 / 取消钮的祖先里不许出现 `Opacity`。时间断言改成按
`searchTransitionMs` 取比例，避免下次改时长又红一片。

**踩到的坑**：`preview_capture_test` 的推入转场中间帧按 120ms 抓（400 档的 0.3）→
换成 90ms（300 档的 0.3）后过渡帧逐像素一致；但紧随其后的**落定搜索页**图
0.01%/44px 差 —— 是输入光标 500/500ms 闪烁的相位随累计时长偏了，把后一段
pump 从 400 改 430（合计仍 520ms）即归零。

全量 282 测试通过；analyze 0 error。
